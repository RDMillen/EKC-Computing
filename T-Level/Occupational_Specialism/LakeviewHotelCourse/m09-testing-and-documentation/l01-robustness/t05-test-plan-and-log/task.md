# Evidence of testing

Automated tests show that your code works. A test log shows it to a reader who does not run your code.

## Task
Fill in `TEST_LOG.md` for your own hotel system:
1. Plan first (before you run anything): number, what is tested, test data, kind of data, expected result.
2. Run each test and record the actual result and pass/fail.
3. For every failure, record the fix and re-test it (regression testing: do the old tests still pass?).

Aim for:
- every requirement in the brief covered by at least one test
- functional tests (price, booking, collision), non-functional (the site responds, pages work on a phone-width window) and
  security tests (SQL injection text, accessing someone else's booking by changing the URL, logged-out access)
- evidence, such as a screenshot filename or the name of the unit test that backs the row.
